# OCS 服务端版 —— 把网课挂在低功耗设备上跑

把 OCS 网课助手从「本机浏览器」搬到家里的低功耗设备（树莓派 / NAS / 旧笔记本）上：设备上跑一个真实 Chromium，脚本和 AI 答题都在那边执行，**你的主力电脑可以关机**。

功耗对比很直观：

| 方案 | 典型功耗 | 说明 |
| --- | --- | --- |
| 主力台式机挂一夜 | 80–250 W | 显示器关了，主机还在跑 |
| 旧笔记本 | 10–25 W | 盖盖子也能跑 |
| 树莓派 4B / 5 | 3–7 W | 无风扇，放角落就行 |
| x86 NAS（待机+挂课） | 10–20 W | 本来就 7×24 开着 |

按 8 小时/天、电费 0.6 元/度算，从 150W 换成 5W，一年省下的电费大约 250 元——比设备本身还贵。

## 零、Windows 电脑：装个 exe 就行

只想在自己的 Windows 电脑上用，不需要命令行，也不需要装 Node：

1. 下载 `OCS-Setup-2.8.1.exe`（24MB）；
2. 双击 → 下一步 → 完成；
3. 桌面双击「OCS 网课助手」——**不会弹黑窗口**，图标直接出现在任务栏右下角，浏览器自动打开控制台。

| 项 | 说明 |
| --- | --- |
| 运行时 | 自带 Node.js，不用另装 |
| 浏览器 | 用系统自带的 Microsoft Edge（Win10/11 都有），所以安装包只有 24MB |
| 安装位置 | `%LOCALAPPDATA%\Programs\OCS`，**不需要管理员权限** |
| 数据 | 同目录下 `app\data`，卸载时默认保留（登录态不用重扫） |
| 端口 | 默认 `8899`，被占用会自动换一个；已经在跑就直接打开，不会起第二个 |
| 后台运行 | 无窗口，常驻任务栏右下角（通知区域）。**双击**图标 = 打开控制台，**右键** = 查看日志 / 重启 / 退出 |
| 日志 | `app\data\ocs.log`，右键托盘图标可以直接打开 |
| 停止 | 右键托盘图标 → 退出（后台不会留进程，Job Object 会把 node 一起带走） |

> **第一次运行会弹「Windows 已保护你的电脑」**：安装包没有购买代码签名证书，SmartScreen 对陌生 exe 一律拦。
> 点「更多信息」→「仍要运行」即可，不是病毒。介意的话可以自己按下面的方式从源码构建。

装完直接看「三、首次使用：登录」。后面「一、二」是 Linux / NAS / 树莓派 的部署方式。

### 自己构建安装包

Windows 机器上不需要装 Windows SDK，Linux 也能交叉编译：

```bash
sudo apt install nsis gcc-mingw-w64-x86-64
bash packaging/build-windows.sh
# 产物：dist/OCS-Setup-<版本>.exe
```

脚本会自动下载 Windows 版 Node（约 34MB，缓存在 `packaging/vendor/`）、编译启动器、打包 `src` + `userscript` + `playwright-core`。
换 Node 版本：`NODE_VER=v22.23.4 bash packaging/build-windows.sh`。

## 一、先做这一步：环境自检

**不要跳过。** 服务端挂课唯一的技术门槛是「视频能不能解码」。少数设备/构建缺 H.264 解码器时的表现非常隐蔽——页面正常、脚本正常、但视频进度条一动不动，所以用真实播放来验证，而不是看文档猜。

```bash
cd ocs-server
npm install --omit=dev
node scripts/diagnose.js
```

输出里最重要的一行是：

```
✓ 真实播放测试通过：已解码 160x120，进度 1s
```

- **通过** → 继续往下走。
- **失败（H.264 不可用）** → 按脚本给出的提示换浏览器，详见文末「故障排查」。

## 二、部署

### 方式 A：树莓派 / 旧笔记本（裸机，推荐）

裸机部署能用系统自带的 Chromium，**这是 H.264 最容易正常工作的方式**（Raspberry Pi OS 的 chromium 带硬件解码；Debian 12/13 的 chromium 也通常已自带 H.264）。

```bash
# 1. 装依赖（Debian / Raspberry Pi OS）
sudo apt update
sudo apt install -y chromium nodejs npm fonts-noto-cjk fonts-noto-color-emoji

# 2. 放代码（假设放在 /opt/ocs-server）
sudo mkdir -p /opt/ocs-server && sudo chown $USER /opt/ocs-server
# 把本目录内容拷进 /opt/ocs-server

cd /opt/ocs-server
npm install --omit=dev
node scripts/diagnose.js     # 必须通过
npm start
```

看到 `控制台已启动： http://<本机局域网IP>:8899` 就成功了。用手机或电脑浏览器打开这个地址。

**设置开机自启**（可选但强烈建议）：

```bash
sudo cp deploy/ocs-server.service /etc/systemd/system/
sudo nano /etc/systemd/system/ocs-server.service   # 改成你的路径和用户名
sudo systemctl daemon-reload
sudo systemctl enable --now ocs-server
sudo journalctl -u ocs-server -f                   # 看日志
```

#### Debian 服务器（无桌面）补充说明

先确认三件事：

```bash
uname -m                # x86_64 还是 aarch64
cat /etc/debian_version # 11 / 12 / 13
node -v                 # 必须 >= 18
```

| 事项 | 说明 |
| --- | --- |
| Node 版本 | Debian 12 自带 18，够用；**Debian 11 只有 12，必须升级**（NodeSource 或 nvm） |
| 桌面环境 | 不需要，服务默认无头运行，无需 X11 / Xvfb |
| 中文字体 | **必装** `fonts-noto-cjk`，否则 OCS 面板中文全是方框 |
| 运行身份 | 用普通用户跑；`--no-sandbox` 已内置，root 也能启动但不建议 |
| `/dev/shm` | 启动参数已带 `--disable-dev-shm-usage`，小内存机器不易崩 |

```bash
sudo apt update
sudo apt install -y chromium fonts-noto-cjk fonts-noto-color-emoji
```

Debian 12/13 的 chromium 一般已自带 H.264，装完先跑自检确认，不要凭经验假设。

#### 关于硬件解码

这一版按**软解**跑，不启用 GPU 加速。理由很实际：软解一路 1080p 约占 20%~30% 单核，家用设备挂 2~3 个账号完全撑得住；而 Chromium 在无头模式下要真正吃上硬解，得看显卡、驱动、启动参数三样配合，不同机器结果差别很大，调起来比挂课本身还费时间。

如果以后确实需要把 CPU 降下来，再单独处理，不影响现在这套跑课。

### 方式 B：NAS / x86 设备（Docker）

```bash
cd ocs-server
docker compose up -d --build

# 先验证容器里的解码能力
docker compose run --rm ocs node scripts/diagnose.js
```

> 首次构建要装 chromium 和一堆系统库（约 300–400MB）。国内网络直连 `deb.debian.org` 很慢，
> 建议先在 `Dockerfile` 里把 `deb.debian.org` 换成国内镜像源（如 `mirrors.tuna.tsinghua.edu.cn`），
> 否则大概率卡在 `apt-get install` 这一步十几分钟不动。
>
> 如果你只是想让服务跑起来、不在意 Docker，**方式 A 的裸机部署更省事，也更容易拿到 H.264**。

> ⚠️ 容器里的 chromium 是否带 H.264 取决于基础镜像版本，以 `diagnose.js` 的结果为准。
> 如果自检失败，有两个选择：
> 1. 把宿主机的 Chrome 挂进容器（见 `Dockerfile` 顶部注释）；
> 2. 放弃 Docker，改用方式 A。

### 升级已有部署

**不需要全部替换，也千万不要删掉 `data/` 目录**——里面是配置、cookie、登录态和浏览器 profile，删了要重新扫码登录。包内不含 `data/`，所以直接覆盖解压是安全的：

```bash
sudo tar -xzf ocs-server.tar.gz -C /opt/            # 覆盖代码，不动 data/

```

升级成功的标志是启动日志里带版本号：

```
控制台已启动： http://<本机局域网IP>:8899  (v2.7.1)
用户 3 个：张三、李四、王五
```

#### 从 v2.1 或更早升上来：任务会变成用户

- 原来的每个「任务」自动变成一个「用户」，名字、地址、锁定状态都保留；
- 旧的共享登录态 `data/profile/` 搬给**第一个用户**，它不用重新扫码；
- 旧的 `data/gm-store.json`（AI 配置、题库）也复制给第一个用户；
- 其余用户是干净的 profile，进去登录一次，之后就一直记住了。

迁移只做一次，`config.json` 里的 `tasks` 字段会被 `users` 取代。如果迁移后想换回来，把备份的 `data/config.json` 和 `data/profile/` 放回去即可。

#### v2.7.0：脚本换成 5.4.0 基线，只留 AI 答题

原版 5.4.0 **完全没有 AI 答题**（`searchAnswerByAI`、`chat/completions`、`aiAnswerer` 全为 0 处），
直接替换就会「不答题」。这一版把 AI 答题整套移植回 5.4.0，其余保持一致：

- 脚本版本 **5.4.1**：5.4.0 的功能（学堂在线、雨课堂 V2 的 PPT/讨论任务点、iCourse 配置迁移）全部保留；
- AI 答题完整回归：配置读取、消息构建、字母→选项映射、图片题、超时、日志；
- **题库入口已移除**，界面上只显示「题库配置（已移除）」，答题全部交给 AI；
- 设置面板提示同步改成「本版本只使用 AI 答题」。

同时修掉「题干只读一半」：

- 日志里的 `开始搜题:` 原来被 `slice(0, 20)` **硬截断到 20 字**，看着像没读完，现在输出完整题干；
- 超星题干处理原来会**盲删前两个子节点**。当「题号+题型+正文」挤在同一个文本节点时，
  正文前半段会被一起删掉。现在只剥离题号（`1.` / `（2）`）和题型（`【单选题】` / `(单选题, 2.0 分)`），
  正文一个字都不动。已验证 10 种结构，`2023年…`、`1.5 倍…` 这类数字开头正文不会被误删。

另外修了一个会让答题流程中断的问题：`waitFor` 超时后原本直接 `reject`，
调用方没 catch 就会把整个答题循环打断；现在未指定错误文案时改为「打日志并继续」，指定了才抛错。

#### v2.8.1：后台静默运行 + 地址栏固定入口

**托盘化**：双击 exe 不再弹黑色控制台，程序直接缩到任务栏右下角。

- 右键菜单：打开控制台 / 查看运行日志 / 重新启动服务 / 退出；
- 日志改写到 `app\data\ocs.log`（带 UTF-8 BOM，记事本打开不乱码，超过 8MB 自动滚动）；
- 关窗口这套说法作废了：现在退出走托盘菜单，Job Object 照样保证 node 跟着退；
- 重复双击只会再开一次浏览器，不会起第二个服务（命名互斥量）。

**地址栏语义改了**：左侧每个用户卡片里的地址，现在是**这个用户运行时固定前往的入口**。

- 不随页面跳转变化 —— 答题时章节一直在切，这个框不会再闪；
- 在框里改地址回车，等于把这个用户的固定入口改掉，下次「运行」还去这里；
- 当前真实页面地址看窗口下方那一栏（它才是实时跟随的）。

**修一个会让整个服务挂掉的崩溃**：

```
TypeError: Cannot read properties of null (reading 'frames')
    at TaskRunner.clickByText (src/task.js:635)
    at Timeout.tick (src/task.js:877)
```

看门狗（`setTimeout`）里的 `tick` 还在 `await` 时，用户点了停止，`cleanup()` 已经把
`this.page` 置空；恢复执行后 `clickByText` 直接读 `page.frames()` 就炸了。而这个异常在
定时器回调里抛出，没有任何地方接得住 → 冒到 `uncaughtException` → **整个进程退出，6 个账号一起停**。

三处一起改：

| 位置 | 改法 |
| --- | --- |
| `clickByText` / `sampleProgress` / `detectGate` | 先把 `this.page` 存成局部变量并判空，`frames()` 单独 try |
| `tick` | 整体 try/catch，出错只记一条 warn，5 秒后重来，不往外抛 |
| `server.js` 全局异常 | `uncaughtException` / `unhandledRejection` **只记录不退出**；1 分钟内超过 20 次才判定无法自愈并重启 |

#### v2.8.0：Windows 一键安装包

不用再装 Node、不用敲命令，双击 exe 就能用：

- **自带运行时不带浏览器**：Node.js 打进去了；浏览器复用系统自带的 Edge（Win10/11 都有），
  所以安装包只有 24MB，而不是 三四百 MB；
- 原生启动器（C 编译，非批处理）：设窗口标题、UTF-8 输出、启动失败弹中文提示；
- 端口被占用自动顺延；检测到已经有一份在跑就直接开浏览器，不会起第二个；
- 启动器用 Job Object 绑定 node：启动器一退，服务一定跟着退，不会留个进程占着端口；
- 首次运行只监听 `127.0.0.1`，不弹防火墙（想让手机看画面把 `server.host` 改成 `0.0.0.0`）；
- 装到 `%LOCALAPPDATA%\Programs\OCS`，不需要管理员；卸载保留 `app\data`（登录态不用重扫）。

服务端配套改动：

- `/api/ping` 轻量探活接口，启动器用它判断「这个端口上是不是自己人」；
- `browser.executablePath` 为空时自动找 Edge → Chrome（`Program Files` / `Program Files (x86)` / `LocalAppData` 三处）。

构建方式见「零、Windows 电脑」里的「自己构建安装包」。

#### v2.7.1：题库真正删干净，不再「干等两分钟说搜不到」

v2.7.0 只是把题库的**入口**置灰了，脚本里那套题库逻辑还在。只要旧配置里还留着题库 JSON，
答题就会去请求题库而不是问 AI。下面这段日志就是典型：

```
21:32:01 [页面] 开始搜题: 【单选题】国防是人类社会发展与安全需要的产物，萌芽于（）
21:34:11 [页面] 答题完成: … {requested: false, resolved: true, searching: true, error: 搜索不到答案…}
```

三个特征能对上：

- `requested: false` —— 请求线程两分钟里**一次都没结束**；
- 中间**没有任何 `[AI 答题]` 日志** —— `searchAnswerByAI` 根本没被调用；
- 2 分 10 秒 ≈ 题库请求 120 秒超时 + 5 秒兜底 + 外层 10 秒余量。

这一版把题库从每一层都删掉：

| 层 | 改动 |
| --- | --- |
| 脚本搜题 | `defaultAnswerWrapperHandler` 只调 AI，传进来的题库参数直接忽略 |
| 脚本缓存 | 不再先查「题库缓存」，每题直接问 AI（以前缓存查询卡住也会让流程停在「开始搜题」） |
| 脚本判断 | `hasAnswererSource` 只看 AI 是否就绪，不再看题库 |
| 脚本配置 | 启动时把残留的 `answererWrappers` 清空 |
| 服务端 | 不再往 GM 存储写题库；`config.json` 里的 `answererWrappers` 自动删除 |
| 控制台 | 删除「题库配置（JSON 数组）」输入框，换成一行说明 |

顺带把诊断做扎实：

- AI 没配好时**立刻**报「还没有配置「AI 答题」…」，并打
  `[AI 答题] 未就绪：enabled=… baseUrl=… model=… key=…`，不再静默等两分钟；
- AI 日志同时写浏览器控制台和 OCS 日志面板，服务端 `[页面]` 里能直接看到；
- 等待上限改成按「AI 超时 × 重试次数」计算，调大 AI 超时后不会被外层提前判死。

升级后第一次启动，`config.json` 里的题库字段会被删掉；各用户的 `gm-store.json`
会在下次打开浏览器时清空题库。

#### v2.6.1：修「答题卡在『开始搜题』不动」

现象：日志停在 `开始搜题：【单选题】xxx`，之后几分钟没有任何输出，页面像死机。

真正的原因不是卡死，是**超时配置形同虚设**，而且出错时什么都不显示：

- 页面里所有请求都走 `GM_xmlhttpRequest`（由服务端桥接到 Node 再发），
  桥接层默认 30 秒就掐断，**你在「AI 答题」里设的 60 / 120 秒根本没传下去**；
- GM 的超时回调 `ontimeout` 没有实现，只处理了 `onerror`——在 Tampermonkey 里
  超时是走 `ontimeout` 的，结果是「什么都不发生」，Promise 一直挂着；
- `onerror` 抛出来的是对象，转成字符串就变成 `[object Object]`，报错看不出原因。

修复：

- 把配置里的超时真正传到请求层（AI 和题库两条链路都改了），
  底层比外层早 2 秒超时，这样能拿到「请求超时」这种明确原因；
- 补齐 `ontimeout` / `onabort`，错误统一转成带 message 的 `Error`；
- 搜题全过程可见：
  `[AI 答题] 请求 gpt-4o-mini：国防的内涵（超时 60 秒）` → `[AI 答题] 已返回（2.3s）：B`，
  失败则 `[AI 答题] 失败（60.0s）：请求超时（60 秒内无响应）`。

**算一下最坏等待**：单题 = 超时 × (重试 + 1)，默认 60 秒 × 2 = 2 分钟；
题目串行搜（并发数在「答题」设置里），3 题就是 6 分钟。觉得慢就把超时调到 25–30 秒，
或者把并发调成 2–3。

#### v2.6.0：内存压缩，一个账号不再吃 2GB

6 个账号 12GB 的主要来源不是「Chromium 本身」，是**标签页数量和站点隔离**：
每个标签一个 renderer，超星页面又是一堆 iframe，聊到后面一个账号能挂 6–7 个渲染进程。

这一版做了四件事（都在「配置 → 内存」里，默认全开）：

- **同站进程合并**（`--process-per-site` + 关闭站点隔离试运行）：同一站点的 iframe、标签共用一个 renderer；
- **低内存设备模式**：栅格缓存、后台缓存都按小内存设备来；
- **单页面 JS 堆封顶**（默认 1024MB）：挂一晚上不会涨到 1.5GB，页面真需要更多时可调大或设 0；
- **定时回收**（默认 10 分钟）：让每个页面做一次 GC，后台页再释放一次渲染缓存；
- **标签页上限**（默认 3 个）：以前是 4 个；锁定模式不受限制，手动开的页面不会被关。

沙箱实测（同一台机器、同样的超星式多 iframe 页面）：

| 场景 | v2.5.7 | v2.6.0 |
| --- | --- | --- |
| 1 个标签页（5 个 iframe） | 1339 MB | 1024 MB |
| 3 个标签页（3 个站点） | 2312 MB | 1700 MB |

省下来的主要是 renderer 数量：3 标签从 7 个渲染进程降到 3 个。
H.264 视频在同样参数下验证可正常播放（`readyState=4`，进度正常走）。

#### v2.5.7：修「单独配了 AI，跑一会儿又不答题了」

真正的根因是**配置被自己覆盖**，不是没保存：

- 页面里任何一个 iframe（超星的章节内容、题目、视频都是 iframe）导航一次，
  服务端会把**全局 AI** 重新灌进这个 frame；
- frame 里的配置写回共享的 GM 存储后，还会广播给同一账号的所有 frame；
- 于是这个账号的独立接口/Key 被全局那份盖掉。如果全局 AI 已经关掉，
  AI 直接变成「未启用」，又没有题库，就表现为**完全不自动答题**；
- v2.5.7 起，iframe 导航、刷新、锁定拉回都统一使用「按用户解析后」的配置，
  不会再回退成全局。保存独立配置后日志里的 `AI 已启用(模型名)` 就是实际在跑的那套。

#### v2.5.6：单独配 AI 不再「配了像没配」

功能没变，改的是「看不出来有没有生效」这件事：

- 保存某个用户的 AI 后，控制台日志直接写两行：切成了哪套接口、推送到几个页面；
- 页面正忙（跳转中 / 脚本没初始化）时不再默默失败，会提示「刷新一次即可」，等待时间从 6 秒放宽到 10 秒；
- 没勾「单独配置」却往灰表单里填了内容，保存前会问一句，不会白填；
- 地址或模型留空时会提示「这一项会沿用全局」，避免以为配了独立接口；
- 新增「清空这个用户已保存的独立 Key」，以前只能覆盖、清不掉；
- 保存后弹窗不关，直接显示实际在用的模型、Key 来源、是否启用；
- 保存全局 AI 时，日志会说明几个账号跟随全局、几个账号有独立配置不受影响——
  「改了全局却不生效」多半就是某个账号配过独立的。

#### v2.5.5：重启回到上次的页面，窗口可以单独关

- **关掉服务再开，自动回到原处**：不用再点一遍用户、翻一遍课程。启动时会打开上次看的那个账号的浏览器，
  直接停在关闭时的地址（课程页、作业页、考试页都算）；前端也会自动选中同一个人。
- **窗口可以单独关**：卡片上多了「关窗 / 开窗」。关掉只释放内存，登录态和上次的地址都留着，
  需要时点「开窗」直接回到那一页，不用重新登录。
- **日志历史不丢**：重启后控制台会把上一次运行的最后 300 行读回来，
  「昨天怎么停的」不用再去翻 `data/logs/server.log`。
- 想彻底停下任务仍然用「停止」；「停止」和「关窗」都会让重启后不再自动开窗，
  区别是停止会结束任务，关窗只是把浏览器收起来。
- 配置 → 运行 → **启动后回到上次关闭时的页面** 可以关掉这个行为（默认开）。

#### v2.5.4：每个用户可单独配置 AI 接口

- 用户卡片新增 **AI** 按钮：可以给某个账号单独配服务商、模型和 Key，其他账号不受影响；
- 典型用法：几个号额度分开算、有人走本地 Ollama 有人走云端、某个号不配 AI 只靠题库；
- 未填的项回落到全局；Key 留空保留原值，回显只显示「已配置」，不把明文发到浏览器；
- 保存后该账号已打开的页面立即切换，连「AI 识别加密字」用的也是他自己的接口；
- 顺带修了「测试连接」按钮的一个老问题：借桥接发请求时拿错了对象，点了必报 `probe.http is not a function`。

#### v2.5.3：人脸核验支持上传视频

- 「人脸核验」新增**上传视频**：视频在控制台本地循环播放，页面抓拍（包括进入课程后的中途抓拍）拿到的都是视频里的画面；
- 页面抓拍完自己关流后不再结束会话，视频源转入**「视频待命」**，下次抓拍自动续上，一条视频管一整节课；
- 待命时推帧降到约 1 秒一帧，省 CPU；画面按 4:3 居中裁切，竖屏或超宽视频不变形；
- 顺带修了面板被通用样式压到 720px、按钮挤成两行的问题。

#### v2.5.2：人脸核验（摄像头接管）

- 进课程/考试时页面要摄像头，不再卡住：`getUserMedia` 被接管，画面由控制台提供；
- 顶栏新增「人脸核验」入口，有请求时变黄并带角标，日志同步提示；
- 支持两种画面来源：**实时摄像头**（能过活体检测）和**上传照片**（任何设备可用）；
- iframe 自动补 `allow="camera; microphone"`，跨域人脸组件也能接管；
- 画面只在内存里转，不写磁盘，服务重启即清空。

#### v2.5.1：用户脚本同步到 OCS 5.3.1

内置脚本从 5.3.0 升到 **5.3.1**，上游这次改的东西正好都在答题主链路上：

- **答案匹配更准**：题干里的 LaTeX 会先线性化（`\frac{1}{2}` → `(1)/(2)`、`\sqrt{2}` → `√(2)`）再比对；
  选项里的 `+1` 和 `-1`、`−3` 和 `-3` 不再被当成同一个答案（新增正负号区分）。
- **加密文字识别重构**：识别结果会缓存复用（同一套字体只解一次），触发点从一个增加到六个，
  iframe 里的题目也会还原，不再出现「翻页后题干又变乱码」。
- **本地题目缓存**：答过的题存内存（上限 1MB，超了自动丢最旧的），同一题再遇到直接命中，
  不再每次写进浏览器存储。界面里的日志也改成只渲染新增行，长任务不再卡。

我们自己的改动全部保留并跟着上游重写了一遍：

- **AI 答题**（设置 → 全局设置 → AI 答题）逻辑不变；
- **加密文字识别方式**（font / ai / auto / off）挂在上游新的缓存结构上，
  选 `off` 时只提示一次，不会每题刷屏；
- 自定义参考表地址时，预加载的也是你配的那个地址，不会白下默认表；
- `fetch.apply(this)` 那两处兼容修复照旧（Playwright 下 `this` 不是 window 会报 Illegal invocation）；
- 右上角的版本号现在从脚本头部自动读，不再写死，换脚本不用改代码。

#### v2.5.0：新增资源面板、一键清理、省资源

- 顶栏多了内存指示，点开是资源面板（Node / 浏览器 / 磁盘 / 每用户明细 / 一键清理）；
- 配置里多了「省资源」，可以拦统计域名、第三方资源、图片、字体、音视频；
- `config.json` 会自动补上 `browser.resourceSaver`，旧配置不用手改；
- 为了把状态接口从几十 KB 降到 1KB，`/api/state` **不再返回完整 `config`**（配置单独走 `/api/config`）。
  升级后如果页面显示空白或按钮没反应，**强制刷新一次**（Ctrl+Shift+R）即可，前端已加 `no-store`，之后不会再缓存旧页面。

#### 如果你之前用的是多账号版（v1.3–v1.5）

会**自动迁移**，不用手动改配置：

- 「账号 1」的任务列表变成唯一的任务列表；
- `data/accounts/a1/profile/` 搬到 `data/profile/`，登录态保留，不用重新扫码；
- 其他账号的目录原样留着（不删），只是不再被这个实例读取。想继续挂它们，在控制台里新建用户，再把对应目录挪成 `data/users/<新用户id>/profile` 即可。

迁移只发生一次，日志里会看到「用户 N 个」，列表对得上就说明没问题。

如果只想替换个别文件，按这张表来（只换一部分容易版本错配，建议整目录覆盖）：

| 路径 | 是否更新 | 说明 |
| --- | --- | --- |
| `src/*.js` | 必须，整个目录 | 各模块互相调用，缺一个就可能启动失败 |
| `src/public/index.html` | 必须 | 控制台界面 |
| `userscript/ocs.common.user.js` | 看你改过没 | 你换过自己的脚本就先备份 |
| `scripts/diagnose.js` | 建议 | 自检工具，不影响运行 |
| `data/` | **绝对不要覆盖** | 配置、登录态、浏览器 profile |
| `node_modules/` | 可覆盖 | 依赖没变，覆盖无副作用 |

## 三、首次使用：登录

服务端没有屏幕，所以第一次登录通过控制台「投屏」完成：

1. 浏览器打开 `http://<设备IP>:8899`；
2. 在「用户」里填一个名字 → **新建用户**，服务会立刻给它开一个独立浏览器；
3. 在这个用户的地址栏粘课程地址、回车（或点「前往」）；
4. 打开右上角「实时刷新」，右侧会出现这个用户的实时画面；
5. 在画面上直接点击二维码 / 输入框，配合下方的「输入文本 / 回车」完成登录；
6. 登录成功后 **cookie 会写进 `data/users/<用户id>/profile/`**，卡片上出现绿色的「已存登录」，以后重启、关机再开都不用重新扫码。

> 控制台里的点击会自动换算坐标，点哪儿就是哪儿，不用调分辨率。

### 多个账号：一个用户一个浏览器

要挂第二个账号，直接在控制台点「+ 新建用户」，填个名字就行，不用再起第二个服务、也不用开第二个端口。

| 对比项 | 旧做法（一账号一实例） | 现在（一个用户一个浏览器） |
| --- | --- | --- |
| 登录态 | 各自 `data/profile` | **各自 `data/users/<id>/profile`**，cookie、localStorage、历史都分开 |
| 互相影响 | 完全隔离 | 完全隔离，一个卡死不影响别人 |
| 端口 | 每个实例一个（8899/8900…） | **一个端口、一个控制台** |
| 内存 | 每实例 ~245MB（含 node 进程） | 每个运行中的用户 ~200–300MB，没在跑的用户不占内存 |
| 操作 | 换端口、换页面 | 同一个页面里切换 |

停掉某个用户（点「停止」）会关掉它的浏览器进程，**登录态已经写在磁盘上**，下次点「运行」直接是登录状态。
没在运行的用户完全不占内存，只占一点磁盘（一个 profile 大约 30–80MB）。

资源参考（实测，headless + 1280x800，软解）：

| 同时运行的用户 | 内存（PSS） | CPU（同时播放 1080p） |
| --- | --- | --- |
| 1 | ~250 MB | 20%~30% 单核 |
| 3 | ~750 MB | 60%~90% 单核 |

> 同一出口 IP 挂多个账号时，平台可能会风控。目前所有用户共用一份 `browser.userAgent`，
> 如果确实需要区分设备指纹，可以再说，不必为了这点先上多实例。

## 四、配置 AI 答题

点右上角 **⚙️ 配置**：

1. 勾选「启用 AI 答题」；
2. 选服务商预设（DeepSeek / 通义 / Kimi / 智谱 / 硅基流动 / OpenRouter / 本地 Ollama…），会自动填好接口地址和模型；
3. 填 API Key；
4. 点 **测试连接**，看到 `✅ 连接成功` 再保存；
5. 保存后**运行中的页面立即生效**，不用重启。

AI 与题库的关系、答案格式约定、成本控制，见同目录的 `AI答题说明.md`。

服务端版的配置不是只改改内存：

- 保存时会写进 GM 存储（`data/gm-store.json` 里的 `common.settings.aiAnswerer`），**每新建一个页面、每进一个新章节都会自动带上**，不会出现「刚配好、一换页就失效」；
- 任务启动后日志会有一行 `配置已生效：AI 已启用(模型名)`。如果这里写的是「未启用」，说明配置没保存成功，回配置页再点一次保存；
- 答题过程会以 `[页面] ...` 的形式转进日志（读题、搜题、AI 返回、提交），作业页到底跳过了哪一步，看这里最快；
- 这里是**全局默认**，所有用户共用。要让某个账号走别的服务商或另一个 Key，见下一节。

### 给某个账号单独配 AI

1. 在左侧用户卡片上点 **AI**；按钮变蓝说明这个账号已经是独立配置；
2. 勾选「这个用户单独配置」，改服务商、模型、接口地址或 Key，随便改哪几项都行；
3. 点「测试这个接口」确认能通，再保存。

**不需要重启服务，也不需要重启浏览器。** 保存后当前页面 1~3 秒内就会换过来，下一道题走新接口；
页面正忙（跳转中、脚本还没初始化）时最多等 10 秒，控制台日志里会写清楚推送到几个页面。
实在没动静就刷新一次这个用户的页面，配置本身已经存好了，不会白配。

规则：

- 没填的项沿用全局（比如只换模型、地址留空）——**地址和模型都留空就等于没换，还是全局那套**；
- Key 留空表示不改，继续用原来保存的那个；想清空勾「清空这个用户已保存的独立 Key」；
- Key 只写在本机 `data` 目录（`config.json` 的 `users[].ai` 和对应用户的 `gm-store.json`），控制台前端只拿到「有没有配 Key」，不回传明文；
- 「AI 识别加密字」也走这个账号自己的接口，不吃别人的额度；
- **勾了「单独配置」才算数**：没勾时表单是灰的，填了也不会保存——现在点保存会先问你一句，避免白填；
- **改全局只影响「跟随全局」的账号**。某个账号配过独立接口，改全局对它没有任何影响，
  这是「明明改了却不生效」最常见的原因。保存全局时日志会写明几个人跟随、几个人不受影响。

保存后控制台日志会出现两行，能直接确认有没有生效：

```
[张三] AI 接口已切换为独立接口 gpt-4o-mini（独立 Key）
[张三] 新的 AI 配置已推送到 1 个页面，正在答题的话下一题就会用新接口
```

如果写的是「页面还没准备好……刷新一次即可」，说明页面当时在跳转，刷新就好。

如果作业页**一道题都不答就跳走**，先看两行：`配置已生效：AI 已启用(...)` 有没有出现、`[页面]` 里有没有搜题记录。
把这两段日志发我，就能定位是没识别到题目，还是 AI 请求被拦。

### 加密文字：三种识别方式，自己选

有些题目的文字用**自定义字体**渲染：DOM 里存的是 `ABCDEFG` 这种乱码，浏览器用平台下发的字体文件
把它画成「知识就是力量」。不还原的话，题库和 AI 拿到的都是乱码，只能跳过。

控制台 → 配置 → **加密文字 → 识别方式**，四选一：

| 方式 | 原理 | 适合 |
| --- | --- | --- |
| `font`（默认） | 把字体文件里的字形栅格化，和本地参考表 `font_ref_cx.bin` 比对，反查出真实汉字 | 绝大多数超星作业页，快（几十毫秒~几秒）、不花 token |
| `ai` | 脚本把每个乱码字符用**同一个加密字体**画到 canvas 上（带编号的网格图），交给支持视觉的模型逐格读，再回填 DOM | 参考表拉不到、或者平台换了字体导致特征比对不准 |
| `auto` | 先用 `font`；字体不可用、或认不准的字超过六成时整段转 `ai` | 想省心就选它：能本地解决的本地解决，解决不了才花钱 |
| `off` | 不还原，乱码直接交给题库 / AI | 只想看原始表现、排查问题 |

`ai` 方式走的是 GM 桥接，不是页面直接发请求，所以：

- 不受「https 页面不能请求 http 服务」的限制，也不用开 CORS；
- 每批默认 24 个字一张图（`aiBatch` 可调 6–60），一张图几十 KB，几秒钟返回；
- 需要先在上面的「AI 答题」里启用并填写**支持图片**的模型（`允许发送图片` 不能被关掉）。

日志里会看到这样的三行，能确认到底走的哪条路：

```
[页面] [加密] 加密文字：使用 AI 视觉识别（28 个不同字符）
[AI识别] 收到字形图 63KB，共 24 格
[页面] [加密] 加密文字识别完成（AI 视觉，28 字），耗时 0.9 秒
```

`font` 方式成功时是 `加密文字识别完成（字体特征，N 字）`；`auto` 转 AI 时会写明 `AI 视觉（自动回退）`
或 `字体特征 + AI 复核`。失败会写 `加密文字识别失败：原因`，并弹出提示，不会卡住答题流程。

想直接改配置文件也可以，`data/config.json`：

```json
"ocs": {
  "cryptoText": {
    "mode": "auto",
    "aiBatch": 24,
    "refTableUrl": "https://cdn.ocsjs.com/resources/font/font_ref_cx.bin"
  }
}
```

## 五、控制台能做什么

| 区域 | 功能 |
| --- | --- |
| 用户 | 只填名字就能新建，**一个用户 = 一个独立浏览器 + 一套独立登录态**，可以同时跑多个 |
| 用户卡片 | 名称 + 地址栏 + 前往 + 运行/停止/锁定/删除，地址随时可改；绿色「已存登录」表示登录态已落盘 |
| 实时画面 | 显示当前选中用户的画面，1fps 投屏，支持单击、**双击**、输入、滚动；点「放大」进全屏；地址栏右侧的 `1/2` 是标签页切换 |
| 日志 | 实时 SSE 推送，带用户标签；注入成功、配置生效、页面跳转、异常都在这里 |
| 配置 | AI 接口、**加密文字识别方式**、**省资源**、**内存（紧凑模式 / 堆上限 / 标签页上限 / 定时回收）**、自动开始、网页尺寸、渲染倍率、User-Agent |
| 按用户 AI | 每个用户卡片上一个 **AI** 按钮：单独指定服务商 / 模型 / Key，或保持跟随全局 |
| 资源 | 顶栏实时显示内存占用，点开是资源面板：Node / 浏览器 / 磁盘、每个用户明细、曲线、一键清理 |
| 人脸核验 | 顶栏入口，页面要摄像头时变黄提示；点开用**本机摄像头**、**上传照片**或**上传视频**给页面供画面，视频可跨多次抓拍待命续上 |

### 用户 = 一个独立浏览器 + 独立登录态

新建用户只需要一个名字，服务会立刻给它开一个独立浏览器；把地址粘到卡片里的地址栏、回车（或点「前往」）就开始。

- **每个用户一个浏览器进程**，互不排队：A 在挂课，B 可以同时在刷题，C 停在登录页等你扫码；
- **登录态各自保存**：A 的 cookie 不会跑到 B 那里，B 也不会把 A 顶下线；
- 点卡片任意空白处，右侧画面切到那个用户；地址栏、点击、滚轮都只作用于它；
- 「停止」关掉这个用户的浏览器（登录态保留在磁盘），其他用户不受影响；
- 「删除」会把这个用户的**整个数据目录**一起删掉，包括登录态和浏览历史，下次要重新登录。

每个运行中的用户占一份内存，**实测 400–750MB**（跟页面复杂度有关，超星的作业页偏重）；停着的用户不占内存。
v2.6.0 起默认开启内存紧凑模式：同站进程合并、标签页最多 3 个、每 10 分钟自动回收一次，
同样 3 个标签页的账号从约 2.3GB 降到约 1.7GB（沙箱实测，见下面「内存」一节）。

### 双击

有两种用法，都指向同一个动作：

| 操作 | 效果 |
| --- | --- |
| 在画面上双击 | 直接对那个位置发双击（页面收到 click → click → dblclick，和真实鼠标一致） |
| 点画面右上角的「双击」按钮 | 对**上一次点击的位置**双击；还没点过就双击页面中心 |
| 放大后点底部的「双击」按钮 | 同上，手机上没有双击手势时用这个 |

按钮点完会弹一行 `已双击 (x, y)`，方便确认点在了哪里。想换位置就先在画面上单击一下，再按「双击」——
单击只发单击，不会触发双击元素。

### 点击后跳转会在日志里说明

在画面上点击（或在地址栏按回车）之后，如果触发了页面跳转，日志会先写一条：

```
[任务A] 即将跳转到：https://mooc1.chaoxing.com/mycourse/studentstudy?chapterId=...
```

如果站点是在前端换路由、没有真正发请求，则会退一步写 `页面已跳转到：...`。这样画面一变你就能对上是跳到哪了，
尤其是被平台踢回登录页、或者点了「开始学习」被带去新章节的时候。

### 在新标签页打开的链接会自己跟过去

很多平台把「作业」「章节」「资料」做成 `target="_blank"` 或者用 `window.open` 打开，点下去画面就停在原地——
因为新页面是一个**新的标签页**，不是当前这一页在跳转。

现在会处理：

- 点开后，画面自动跟到新标签页，日志写 `点击打开了新标签页，已跟随：https://...`；
- 新标签页里同样会注入脚本、写入 AI 配置（日志会再报一次 `新标签页配置已生效`）；
- 地址栏右侧的按钮会变成 `1/2`，点它在标签页之间循环切换，回到原来那页；
- 关掉其中一个标签页会自动切回上一个，不会黑屏；
- 标签页超过 4 个会自动关掉最早的，避免挂一晚上攒出十几个页面占内存。

**锁定模式下不自动切页**（锁定的含义就是钉在这一页，切走会打断挂课的进度统计），
新页面会在后台打开并写一条日志 `已在新标签页打开：...（锁定模式不切页，可点标签按钮切换）`，
需要时手动点标签按钮过去。

### 画面是什么时候截的

**只有控制台页面来要，服务端才截。** 没有后台定时录屏、没有录像存盘、也没有主动推流：

| 场景 | 是否截图 | 频率 |
| --- | --- | --- |
| 控制台页面关闭 / 掉线 | 不截 | 0 |
| 开着，但取消勾选「实时刷新」 | 只在你点击画面后截 | 按操作 |
| 开着，勾选「实时刷新」（默认） | 持续 | 1 张/秒 |
| 放大全屏时 | 持续，且用高清截图 | 1 张/秒 |

也就是说，**关掉网页 = 零开销**，服务器只跑浏览器和答题，不产生任何截图。截图只在内存里返回给控制台，不写磁盘、不上传外网。

1 张 1280x800 的缩略图约 30ms CPU、47KB（实测静态页；视频页会更大）。多个设备同时看不会成倍叠加——同一瞬间到达的请求会合并成一次截图。

### 画面放大与滚动

点画面右上角「放大」进入全屏：

- **滚轮** = 滚动页面（手机上单指上下滑）；
- **单击** = 点击页面，坐标自动换算，扫码登录仍然可用；
- **Esc** 退出。

放大时请求的是高清截图。如果觉得放大后发虚，把「配置 → 渲染倍率」改成 **2x**（需重启服务），
画面会按 2 倍设备像素截取，代价是内存和流量翻倍。

### 锁定：固定当前界面持续执行

用户卡上的「锁定」用于**把浏览器钉死在某个页面**，适合刷题页、讨论区、签到页这类不能跳走的地方：

| | 普通运行 | 锁定运行 |
| --- | --- | --- |
| 无进度处理 | 15 分钟后刷新，重试 2 次后结束 | 不刷新，一直等着 |
| 单次运行时长 | 不限，直到课程结束或手动停止 | 不限，直到手动停止 |
| 页面被跳走 | 不干预 | 2 秒内检测到并拉回锁定地址 |
| 队列 | 结束后自动跑下一个 | 一直占着队列，需手动停止 |

锁定点默认记在「点完开始学习后停留的页面」。如果脚本自己跳到了新页面，点任务卡上的
「重锁」把锁定点更新为当前画面所在的地址。连续 5 次被跳走会停止拉回并提示，避免死循环。

> 只比较域名和路径，忽略 `?id=123` 这类参数变化，所以答题时地址栏参数变化不会误触发拉回。

### 资源占用：谁在吃内存，一眼看到

顶栏中间那个 `863 MB` 就是当前总占用（Node + 所有浏览器），超过 1.5GB 会变黄。点它打开资源面板：

| 指标 | 含义 |
| --- | --- |
| Node 内存 | 服务进程本身。正常 100–300MB，持续上涨才是泄漏 |
| 浏览器内存 | 所有 Chromium 进程的 RSS 之和，按 `--user-data-dir` 认领到各自用户 |
| 磁盘占用 | `data/` 目录，含登录态、缓存、本地答题记录 |
| 已拦截请求 | 开启省资源后累计拦下的请求数，按类型分开统计 |
| 事件循环延迟 | 最近 6 秒最严重的一次阻塞。持续 >100ms 说明主线程被卡住了 |

下面的表格按用户拆开：每个用户多少内存、多少 CPU、几个标签页、占多少磁盘。停止的用户不占内存，只占磁盘。

### 内存：6 个账号怎么压下来

顶栏数字变大时，先看是谁占的：一个账号的浏览器内存 = 固定开销（约 450–550MB，主进程 + 网络/存储服务 + GPU）
\+ 每个标签页（约 200–400MB，看页面复杂度）。**关掉一个多余标签页，比调任何参数都管用。**

配置 → 内存 里四个开关：

| 项 | 默认 | 作用 | 什么时候改 |
| --- | --- | --- | --- |
| 紧凑模式 | 开 | 同站进程合并 + 低端设备模式 | 需要最大兼容性时关掉；关掉后内存会回到旧水平 |
| 单页面 JS 堆上限 | 1024MB | 防单个页面无限涨 | 页面提示「内存不足」或白屏时调到 1536 / 0 |
| 每个账号最多标签页 | 3 | 超出自动关最旧的 | 挂课只需要 2 个时设 2；要同时开多个作业页时设 4–5 |
| 定时回收间隔 | 10 分钟 | 定时 GC + 释放渲染缓存 | 内存小（4GB）设 5；嫌 GC 卡顿设 30 或 0 |

改「紧凑模式 / 堆上限 / 标签页」**要重启浏览器**（点卡片上的「停止」再「运行」，或重启服务）；
「定时回收」保存即生效。

还能继续省的：

- 只挂课不答题时，不需要的账号点「关窗」，一个账号立刻回 500MB 左右；
- 开「省资源」里的拦截统计/第三方域名（别拦图片和音视频，会影响题目和进度）；
- 渲染倍率保持 1x，网页尺寸 1280x800 就够，放大到 1600x1000 每个页面多 100MB 左右；
- 6 个账号同时挂 1080p，8GB 内存是下限；4GB 机器建议分两台，或同一时间只跑 3 个。

### 关窗 / 开窗：临时不用的账号先收起来

卡片上的 **关窗** 只关掉这个用户的 Chromium，不动别的账号，也**不删登录态**：

| 操作 | 任务 | 浏览器 | 登录态 / 上次地址 | 重启后 |
| --- | --- | --- | --- | --- |
| 关窗 | 结束 | 关闭，释放内存 | 保留 | 不会自动开，点「开窗」回到原页 |
| 停止 | 结束 | 关闭 | 保留 | 不会自动开 |
| 开窗 | 不启动 | 重新打开并回到上次的页面 | 保留 | — |

卡片状态会显示 **已关闭**，按钮变成 **开窗**。想让他继续挂课，点「运行」；
只是暂时不看、又不想占内存，点「关窗」。

### 重启回到上次的页面

服务启动时会打开**上次看的那个账号**的浏览器，直接停在关闭时的地址：

- 关服务前在看张三的课程页 → 重启后自动打开张三的浏览器并回到那一页；
- 前端也会自动选中张三，右侧画面和地址栏都是他，不用再点一遍；
- 每个用户各自记住自己的最后地址，切换用户时两边都更新；
- 只恢复页面，**不会自动开始答题**；上次在跑的任务点一下「运行」就接着跑；
- 关服务前点过「停止」或「关窗」的账号，重启后不会自己冒出来；
- 不想要这个行为：配置 → 运行 → 取消勾选 **启动后回到上次关闭时的页面**。

### 日志历史

控制台重启后，日志区会把上一次运行的最后 300 行读回来（文件仍然是 `data/logs/server.log`），
用来排查「昨晚挂到一半为什么停了」。点「清空」只清当前显示，不动磁盘上的文件。

### 一键清理：把不用的内存还回去

面板底部两个按钮：

| 按钮 | 做什么 | 影响 |
| --- | --- | --- |
| 清理空闲浏览器 | 把没在跑任务的用户的整个 Chromium 关掉 | 马上释放几百 MB；登录态在磁盘上，下次「运行」自动重开 |
| 清理全部 | 运行中的用户只关多余标签、清 HTTP 缓存、让页面做一次 GC | 不打断任务，视频进度不受影响 |

勾上「同时清磁盘缓存」会额外删掉 `profile/` 里的 `Cache`、`Code Cache`、`GPUCache` 等目录（**不碰 cookie 和 Local Storage**），
一个跑过几天的用户通常能清出几十到几百 MB。

清理完会告诉你「内存 1544MB → 865MB，释放约 681MB」，日志里也有一条对应的 `[清理]` 记录。

### 省资源：不加载用不到的网页资源

挂课真正需要的只有主文档、脚本、同站请求、样式和视频流；剩下大量是统计、广告、推荐图。
配置 → **省资源** 打开后，浏览器会在请求发出前就掐掉它们：

| 选项 | 拦什么 | 建议 |
| --- | --- | --- |
| 拦截统计 / 广告域名 | 内置的百度统计、CNZZ、友盟、GA、双击等 | 默认开，基本无副作用 |
| 拦截第三方域名资源 | 与当前页面不同主域的脚本/图片/字体/媒体 | 更省，但可能影响扫码登录等第三方 SDK |
| 拦截图片 | 所有图片请求 | 会影响**图片题**（题干是图片时看不到） |
| 拦截字体 | 所有字体请求 | 加密文字识别开着时会**自动放行**，否则题干一直是乱码 |
| 拦截音视频 | 所有 video/audio | 会直接**停掉挂课进度**，一般别开 |
| 额外拦截的域名 | 每行一个，含子域 | 站点有特别烦的推荐/统计域名时加 |

- 主文档、`websocket`、同站 `xhr/fetch` 永远放行，不会把页面弄坏；
- `cdn.ocsjs.com`（脚本自己的字体特征表和版本检查）永远放行；
- 开关改完要**重启浏览器**才生效（停止再运行，或新建一个用户）；
- 拦了多少在资源面板的「已拦截请求」里看，日志里每分钟有一条 `[省资源] 累计拦截 ...`。

```json
"browser": {
  "resourceSaver": {
    "enabled": true,
    "blockTrackers": true,
    "blockThirdParty": false,
    "blockImages": false,
    "blockFonts": false,
    "blockMedia": false,
    "allowlist": [],
    "blocklist": ["example.com"]
  }
}
```

### 人脸核验：页面要摄像头时，用你的画面顶替

有些课进课程、进考试前会弹一个人脸核验：页面调 `getUserMedia` 打开摄像头，拍一张照上传。
服务器上的无头浏览器没有摄像头，以前会直接卡在这一步（`NotFoundError`），课根本进不去。

现在这条链路被接管了：页面以为自己在用摄像头，实际画面来自控制台。

**操作步骤**

1. 页面一请求摄像头，顶栏的「人脸核验」会变黄并带数字角标，日志里也会有一行
   `[摄像头] 张三 的页面请求了摄像头，请打开控制台完成人脸核验`；
2. 点顶栏按钮，弹窗左侧是发起请求的用户，右边是画面区；
3. 三选一：

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| 实时摄像头 | 点「打开我的摄像头」，允许浏览器权限 | 画面持续推给页面，**能过眨眼、张嘴、转头这类活体检测**。需要在本机用 `http://127.0.0.1:8899` 打开控制台（https 或 localhost 才允许调用摄像头） |
| 上传照片 | 点「上传照片」选一张正脸照 | 任何设备都能用（手机浏览器会直接给你「拍照」选项）。脚本端会给画面加轻微呼吸感，但**过不了眨眼检测** |
| 上传视频 | 点「上传视频」选一段本人正脸视频 | 本地循环播放，页面每次抓拍拿到的都是视频里的画面。**上传一次就够**：抓拍完页面自己关流后，源转入「待命」，下次再要自动续上 |

4. 实时摄像头、照片模式下，核验完页面自己关摄像头，弹窗会显示「已结束」；
   视频模式不会结束，而是变成**「视频待命」**——视频仍在循环，网课中途再抓拍时自动接着供帧，不用你再点一次。
   点「结束」才真正收尾，点「拒绝」会让页面的 `getUserMedia` 直接失败（等于这次核验放弃）。

**它做了什么**

- 覆盖了 `navigator.mediaDevices.getUserMedia`，返回一条 `canvas.captureStream()` 合成的流；
- 顺手伪造了 `enumerateDevices`（一个名为 `HD Webcam (OCS)` 的摄像头）、
  `permissions.query({name:'camera'})`（直接返回 granted）、`track.getSettings()`（640×480 / 15fps / facingMode: user）；
- 给页面里所有 iframe 补上 `allow="camera; microphone"`——人脸组件常在跨域 iframe 里，不补的话连脚本都进不去；
- 页面要音频时附一条静音轨，避免「只给视频不给音频」被判定为异常设备；
- 视频模式在控制台本地播放（`URL.createObjectURL`），每 110ms 把当前帧画进 640×480 的 canvas 推给服务端，
  和摄像头走同一条链路；进入「待命」后降到约 1 秒一帧，省 CPU 又不让画面变旧；
- 画面走内存中转，**不落盘**，服务重启就没了。

日志里能确认走到哪一步：

```
[页面] [摄像头] 页面请求摄像头，已转交控制台（640×480）
[摄像头] 张三 的页面请求了摄像头，请打开控制台完成人脸核验
[摄像头] 张三 本轮抓拍结束，视频源继续待命
[摄像头] 张三 再次抓拍，视频源已自动续上
[摄像头] 张三 的核验已结束（共 42 帧）
```

**几个限制，先说在前面**

- 摄像头画面是"合成"的：页面如果查 `track.getSettings().deviceId` 之外的硬件特征（比如读 USB 设备名），对不上；
- 上传照片是静止画面加微动，**过不了活体检测**。要过就用实时摄像头或带动作的视频；
- 视频模式需要**保持控制台页面打开**（可以最小化，别关掉）：帧由浏览器从视频里抽，页面一关就没有源了；
  视频编码用 mp4（H.264）或 webm 最稳，打不开时会直接提示；
- 控制台用局域网 IP（`http://192.168.x.x:8899`）打开时，浏览器不允许调摄像头，只能上传照片或视频。
  想在服务器那台机器上直接用摄像头，就在它本机开 `http://127.0.0.1:8899`；
- 一次核验对应一个用户。多个用户同时要摄像头时，左侧列表逐个点，视频源也跟着当前选中的用户走。

### 运行逻辑

- 打开页面 → 等待脚本注入 → 把配置写进页面（所有 frame，含 iframe，**每个 frame 都会重试直到脚本初始化完成**）→ 自动点「开始学习」→ 进入守护；
- 守护期间每 20 秒采样视频进度；**连续 15 分钟无进度**会刷新一次（最多 2 次），仍无进度则判定该课程结束，自动切到下一个用户；
- **单任务不限时长**，会一直守护到课程播完或你手动停止。

想改这些行为（都在 `data/config.json` 里改，改完重启）：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `ocs.maxDurationMinutes` | `0` | 单任务最长分钟数，`0` = 不限 |
| `ocs.stallTimeoutMinutes` | `15` | 多久无进度算卡住，`0` = 不检测、一直等 |
| `ocs.maxReloadTimes` | `2` | 卡住后刷新几次，用完才判定课程结束 |

## 六、故障排查

**视频进度条不动 / 一直播放失败**
跑 `node scripts/diagnose.js`。若「真实播放测试」失败，就是缺 H.264：
- 先看版本：`chromium --version`，Debian 12/13 的 chromium 一般已自带 H.264，老版本升级即可；
- 树莓派（arm64）：用 Raspberry Pi OS 的 chromium，它带硬件解码；
- x86_64：装 Google Chrome 官方 deb，再 `export CHROME_PATH=/usr/bin/google-chrome`；
- 临时绕过：部分平台的播放器会降级到 VP9/WebM，可尝试在配置里把 UA 换成移动端。

**6 个账号吃掉 12GB / 一个账号 2GB**
先看资源面板里这个账号的「标签页」数：每个标签页就是一个渲染进程，200–400MB，开 4 个就 1.5GB 了。
处理顺序：① 配置 → 内存，确认「紧凑模式」是开的（默认开），把「每个账号最多标签页」调到 3 或 2；
② 不需要答题的账号点「关窗」；③ 内存小于 8GB 时别同时挂 6 个 1080p。
v2.6.0 起同样 3 个标签页从约 2.3GB 降到约 1.7GB，详见上面「内存」一节。

**日志里的题干只有半句 / 搜题搜不准**

v2.7.0 之前，`开始搜题:` 这行日志被硬截断到 20 个字，看起来像没读完，实际发给 AI 的是完整题干。
升级后日志会输出全文。如果升级后仍然不完整，看题目在页面上是否分段显示（题号、题型、正文各占一个节点），
或题干里有隐藏文字；把该题截图和日志一并发来。

**日志停在「开始搜题」，几分钟不动**

这不是死机，是在等答题源返回。单题最长等待 = 超时 × (重试 + 1)，默认 60 秒 × 2 = 2 分钟；
题目是串行搜的，3 题就到 6 分钟。v2.6.1 起日志会打出
`[AI 答题] 请求 gpt-4o-mini：题目…（超时 60 秒）`，能直接看出在等哪个模型、等了多久。

想更快失败就把「AI 答题 → 超时」调到 25–30 秒；题目多时把「答题并发」调到 2–3。
如果最后出现 `[AI 答题] 失败：请求超时`，说明这台机器连不上那个接口：
先点「测试连接」，再在服务器上 `curl -I https://你的接口域名` 确认连通性。

**提示「还没有配置「AI 答题」，无法搜题」**
AI 没启用，或者启用但地址 / 模型 / Key 没填全。日志里会紧跟一行
`[AI 答题] 未就绪：enabled=… baseUrl=… model=… key=…`，哪个空了一目了然。
到「配置 → AI 答题」填好，点「测试连接」通过即可。v2.7.1 起题库已彻底移除，只认 AI。

**日志显示「搜索不到答案」，但没看到任何 `[AI 答题]` 输出**
说明这次根本没走 AI。v2.7.1 之前是旧题库配置在生效：题库请求会一直挂到 120 秒超时，
外层再等 10 秒，于是出现「开始搜题 → 两分钟后 → 搜索不到答案」，`requested: false`。
升级到 v2.7.1 后题库链路已被删除，这种情况只可能是 AI 配置未就绪，日志会直接说明。

**给某个账号单独配了 AI，跑一会儿又不答题了（v2.5.6 及更早）**
这是 v2.5.7 修掉的覆盖问题：iframe 导航时灌回全局配置，把独立接口盖掉。升级后即可。
自查办法：控制台日志里该账号显示 `AI 已启用(你配的模型名)` 才算真的生效；
如果显示 `未启用` 或别人的模型名，说明被覆盖了。

**进课程卡在「请开启摄像头 / 人脸核验」**
v2.5.2 起会自动接管。如果还是卡住，按这个顺序查：
- 顶栏「人脸核验」有没有变黄？没有的话说明页面调的不是 `getUserMedia`（可能是平台自己的原生插件，或读摄像头的方式比较特殊），
  把日志里 `[摄像头]` 相关那几行发我；
- 变黄了但画面不动：确认点的是「结束」而不是关窗口；实时模式还要求控制台用 `localhost` 或 https 打开；
- 画面是静止照片、页面提示「未检测到人脸/请眨眼」：换成实时摄像头（照片过不了活体检测）；
- 页面提示「摄像头被占用」：同一时间只给一个用户供帧，切到左侧对应的人再点一次。

**日志出现「加密文字识别失败：Failed to execute 'fetch' on 'Window': Illegal invocation」**
脚本自带的「请求记录」面板在包装 `fetch` 时把 `this` 传错了——它把原生 `fetch` 取出来之后用
`originalFetch.apply(this, ...)` 调用，而这个 `this` 指向面板对象、不是 window，浏览器于是抛
`Illegal invocation`。这段包装一跑，页面里**之后所有网络请求**都会失败，加密字体特征表（`font_ref_cx.bin`）
也拉不下来，就表现为「加密文字识别失败」。

v2.3.1 修了两层：

- 脚本里把调用改成 `originalFetch.apply(window, ...)`（根因）；
- 服务端 GM 兼容层在注入时把 `window.fetch` 预先 `bind(window)`，以后换别的脚本、别处再丢 `this` 也不会炸（兜底）。

升级后重启服务、在控制台点一次「刷新」即可，不用重新登录。

**题目还是乱码 / 日志写「加密文字识别失败」**
先看日志里【加密】那几行，它会把实际走的路径写清楚：

- `已按配置关闭加密文字识别（模式：off）` → 配置里选成了 `off`，改成 `font` 或 `auto`；
- `未检测到加密文字` → 页面里没有 `.font-cxsecret`，说明这题不是加密字体题，乱码另有来源（比如图片题）；
- `加密文字识别失败：...font_ref_cx.bin...` → 拉不到特征表，多半是服务器出不去外网。把 `ocs.cryptoText.mode` 改成 `ai`
  （或 `auto`）就能绕开，不再需要这个文件；
- `AI 识别加密文字失败：AI 答题未启用` → 上面的「AI 答题」没开，或关了「允许发送图片」；
- `AI 识别加密文字失败：HTTP 4xx` → 模型不支持图片。换成 `gpt-4o-mini`、`qwen-vl-*`、`glm-4v` 这类多模态模型。

**页面空白 / 脚本没注入**
看日志是否出现 `OCS 脚本已注入`。没有的话，平台可能不在脚本支持列表里（当前支持超星、知到、职教云、智慧职教、中国大学 MOOC、雨课堂等），或页面加载超时——在控制台点「刷新」重试。

**容器里启动报错 `Failed to launch browser`**
缺系统库。`docker compose` 已用官方 node 镜像并装齐依赖；裸机请按 `diagnose.js` 提示的 apt 包补齐。

**内存被吃满**
Chromium 单实例约 400–700MB。2GB 内存的设备建议只跑一个任务；`docker-compose.yml` 里已限制 1.5GB。

先点顶栏的内存数字看看是谁吃掉的：如果大头是**没在跑任务**的用户，点「清理空闲浏览器」立刻能退回来；
如果运行中的用户标签页很多，点「清理全部」会关掉多余标签并清缓存。还不够就打开「省资源 → 拦截统计/广告域名」，
把页面里那些统计脚本和推荐图先掐掉。

**报错 `JavaScript heap out of memory` / `Ineffective mark-compacts near heap limit`**
v2.0.2 之前的版本有这个问题：页面里每写一次 `GM_setValue`，服务端都会把它转发给**所有 frame**，而且不做合并。OCS 的标签页同步本身会「收到变化 → 再写一次」，两边一撞就成了回环，几秒钟内能放大出上万次跨进程调用，堆内存几分钟被填满。

现在三道闸：同键 120ms 内合并、发起方不再收到自己的广播、同键 3 秒内超过 15 次直接静默 5 秒（日志会写「疑似页面内回环」）。实测同样的写入压力下，旧版 60 秒涨到 2.2GB 后崩溃，新版稳定在 60–300MB 之间锯齿波动。

如果你在日志里看到这条告警，说明页面里有监听器在互相触发——功能一般不受影响，但值得把那段时间的日志发我看看。

**怎么确认内存有没有在涨**

顶栏的内存数字就是总和，点开能看到最近几分钟的曲线（蓝色 Node、黄色浏览器）。
也可以直接问接口：

```bash
curl -s http://127.0.0.1:8899/api/state | grep -o '"mem":{[^}]*}'
curl -s http://127.0.0.1:8899/api/metrics | head -c 600
```

正常是一两分钟内涨到几百 MB 又被 GC 收回去（锯齿状）。如果是只涨不落、越过 1GB 还在爬，就是还有泄漏，把日志发我。

**进程会不会越开越多**
不会，但 `ps` 看着像。正常运行时是 **1 个 node + 一棵 Chromium 进程树**：

```
node src/server.js            ← 1 个，就这么一个
└─ chromium ...              ← 主进程
   ├─ chrome --type=zygote    ← 以下都是它的子进程，正常
   ├─ chrome --type=gpu-process
   ├─ chrome --type=renderer
   └─ ...
```

Chromium 天生是多进程架构，`ps` 里数出十个八个 chrome 属于正常，不是每次启动攒下来的。真正要确认有没有残留，看这两个数：

```bash
pgrep -fc '^node src/server.js'    # 应该等于你开的实例数（单人就是 1）
pgrep -fc -- '--user-data-dir=.*/data/profile'   # 这个实例的浏览器，正常 1
```

数字对不上时，先看端口谁占着：

```bash
ss -ltnp | grep :8899
```

输出为空说明没人占，服务确实没起来；有 PID 就 `kill <PID>`。启动时如果端口被占，日志会直接告诉你占用情况和换端口的命令，不会静默失败。

需要一次性清干净：

```bash
pkill -TERM -f 'node src/server.js'
sleep 2
pkill -f -- '--user-data-dir=.*/ocs-server/data/profile'   # 兜底，正常情况不需要
```

这个版本收到 `Ctrl+C` / `kill` 后最多等 5 秒就会退出，浏览器卡死也不会赖着不走；再按一次 `Ctrl+C` 立即强退。**不要用 `kill -9`**——虽然实测 Chromium 会跟着退，但让它自己收尾更稳妥。

**登录态失效**
平台一般 7–30 天过期。重新在控制台画面里登录一次即可，配置不用重填。

**登录提示「enc 校验失败」**

超星地址里那串 `enc=...` 是用**当前登录身份**加密出来的章节凭证，它跟账号、时间绑死。换账号、复制时少几个字符、放久了，都会失效。服务会这样处理：

1. 打开页面 2 秒内就识别出来，日志写 `[enc 校验失败]`，不再傻等 15 分钟；
2. 自动去掉 `enc`、`cpi`、`_t` 再进一次（超星很多入口不校验 enc，靠 session 重签）；
3. 能进 → 日志提示「已把任务地址更新为上面这条」，任务地址自动落盘；
4. 还是被拦 → 任务直接标记失败并在卡片上红字显示原因，不用自己盯日志。

人工修复的正确姿势，**别从别的设备复制链接**：

1. 在控制台画面里登录（这个实例对应的账号）；
2. 从「课程」正常点进章节（不要直接粘地址），进到学习页；
3. 看控制台底部的地址栏，点右侧复制按钮；或点「锁定」直接把当前页当成任务；
4. 把这个地址填回任务，重新运行。

多账号时特别注意：**每个账号的链接必须各自获取**。账号 A 的 `enc` 拿到账号 B 上跑，一定报这个错。

**平台提示异地/异常登录**
本方案跑在你自己家的局域网 IP 上，通常是设备换了浏览器指纹导致的首次验证，扫码/短信过一次即可。不要同一账号在多台设备同时挂。

## 七、它是怎么实现的

```
低功耗设备
├── Node 服务（Express 风格原生 http）
│   ├── HTTP 控制台 + REST API + SSE 日志
│   └── 任务调度（串行队列 + 守护）
└── Chromium（持久化上下文，cookie 存 data/profile）
    ├── GM API 兼容层  ← 用 CDP 在每个文档前注入，携带最新配置
    └── OCS 用户脚本    ← 原封不动注入，模拟油猴 document-idle 时机
```

三个关键技术点：

1. **`unsafeWindow` 必须定义**，否则脚本会退化成内存存储，刷新即丢配置；
2. **GM 兼容层用 CDP `Page.addScriptToEvaluateOnNewDocument` 注入**，每次导航前重建，保证配置永远是最新的（`addInitScript` 无法移除，会一直用旧快照）；
3. **脚本必须等 `DOMContentLoaded` 再执行**。油猴默认 `document-idle`，而 `addInitScript` 是 `document-start`——此时 `document.body` 还不存在，脚本挂载 UI 会直接抛异常。
4. **资源占用按 `/proc` 算，不猜**。Playwright 拿不到 persistent context 的进程句柄，
   于是按命令行里的 `--user-data-dir=<该用户的 profile>` 认领进程，从 `/proc/<pid>/statm` 读 RSS、
   从 `/proc/<pid>/stat` 的 utime/stime 差分算 CPU。这样多用户各自的内存、CPU 都是真实值，
   用 `du` 统计磁盘（profile 动辄上万个小文件，用 fs 递归会卡住主线程）。
5. **省资源用的是 Playwright 的 `context.route`**，在请求发出前 `abort`，连 DNS 都不解析。
   规则按 resourceType + 主域判断，主域取最后两段（`com.cn` 这类取三段），
   所以 `mooc1.chaoxing.com` 与 `p.ananas.chaoxing.com` 视为同站。
6. **加密文字的 AI 识别不走页面请求，走 GM 桥接**。页面在 https 下，直接 `fetch('http://127.0.0.1:8899/...')` 属于混合内容，会被浏览器拦；
   桥接是 Playwright 的 binding，天然跨过这一层，也不需要在服务端开 CORS。
   图片以 dataURL 传过去（每批 24 字约 30–70KB），Node 侧再拼成 OpenAI 兼容的 `image_url` 请求。
7. **摄像头同样是"换掉底层"，不是模拟点击**。直接覆盖 `navigator.mediaDevices.getUserMedia`，
   返回 `canvas.captureStream(15)` 的流——页面里 `<video>`、`drawImage` 截帧、`MediaRecorder` 全都照常工作，
   因为它拿到的就是一条真实的 `MediaStream`，只是源头是 canvas 而不是摄像头。
   帧从控制台过来：面板把画面 POST 成 JPEG，页面每 180ms 通过 GM 桥接取最新一帧画上去，
   中间不经过任何第三方服务，也不落盘。
8. **视频源是本地播放 + 抽帧，不走服务端转码**。`URL.createObjectURL` 把文件交给控制台的 `<video>`，
   循环播放并每 110ms `drawImage` 一帧推出去——服务端只存 JPEG，不碰视频文件，也不需要 ffmpeg。
   页面那边看到的效果和摄像头完全一样，因为源头仍然是那条 `captureStream`。
9. **按用户配 AI 是"解析"而不是"复制"**。`config.data.ai` 始终是全局默认，用户自己那份只存
   覆盖项，每次注入/请求时由 `user-ai.js` 合成本人配置——所以全局以后新增字段（超时、重试），
   自定义过的账号也能拿到；保存全局也不会把别人的 Key 覆盖掉。
10. **「回到上次页面」记的是 URL，不是整份 DOM**。页面每 2 秒的状态轮询顺手把
   `selectedUserId + pageUrl` 写进 `config.json` 的 `session`，**只在变化时落盘、3 秒合并一次**，
   所以不会因为频繁刷新把磁盘写满。启动时只 `goto` 那个地址，不重放点击、不自动答题——
   登录态本来就在 `profile/` 里，页面加载出来就是关闭前的样子。
   「关窗」只关进程、把 `lastStatus` 标成 `closed`；重启看到 `closed` 就不再自动开，
   这样「主动收起」和「服务被重启」两种情况能区分开。

已实现的 GM API：`GM_getValue / GM_setValue / GM_deleteValue / GM_listValues / GM_addValueChangeListener / GM_removeValueChangeListener / GM_xmlhttpRequest / GM_getTab / GM_saveTab / GM_notification / GM_info / GM_getResourceText / unsafeWindow`。

其中 `GM_xmlhttpRequest` 由 Node 侧发起，**天然没有跨域限制**——这也是放在服务器上的一个额外好处。

```
│   ├── diagnose.js       环境自检（H.264 解码）
├── userscript/           OCS 脚本（含 AI 答题改造版）
├── deploy/               systemd 服务文件（含多开模板）
└── data/                 运行时数据（升级时绝对不要覆盖）
    ├── config.json       配置 + 用户列表（AI Key、题库、上次停留的页面都在这里）
    └── users/
        └── <用户id>/      每个用户一套，互相看不见
            ├── profile/       cookie / localStorage / 浏览历史
            └── gm-store.json  这个用户的答题记录、答题进度
```

`data/` 里是敏感数据：`users/*/profile/` 含登录 cookie，`config.json` 含 API Key。别提交到 Git，别外网暴露。
备份也简单——整个 `data/` 拷走就行，换机器解压回去，所有用户的登录态都在。
